# P1-13/14 receipt dispatcher and current state

R13 adds `protocolV2`, `receiptDispatcher` and `engineState` above the P1-12 JSONL authority. The isolated daemon's authenticated sockets advertise **only `{min:1,max:1}` with no capabilities**. `RemoteClient` installs negotiation after authentication and decryption, before the existing Apple/listener early returns. The network constructor forces the v1 gate even if a dependency passes `testOnlyV2:true`. Ordinary extension windows retain their existing transport and mementos.

R19 supersedes that temporary network gate **only for the fully composed isolated daemon**: recovery, loopback bind and the enrolled development bridge precede installation of its v2 authority. Generic/partial `RemoteServer` construction still forces v1. [P1 exit](p1-exit.md) records shared-JS/bridge/real-disk/RPC/IPC integration evidence and production/P2 limits. Provider sends/controls retain unknown-lane barriers; an unrelated unknown editor/PR/Slack reply does not fence the provider queue.

An in-process harness can explicitly call `currentState.createSocket({authenticated:true,context,sealed:true,testOnlyV2:true,engine,post,close,legacy})`. The trusted context contains the server principal, role, normalized target and seat; `hello.client` and `from` cannot change them. Each socket selects once, has its own application negotiation deadline, and falls through immediately to v1 on its first non-hello frame. Unsupported negotiation closes 1002 without dispatching subsequent work. The in-process opt-in is not an exposed partial-v2 server.

## Receipt boundary

`createReceiptDispatcher({authority,handlers,authorize,now})` requires recovery before admission. `authorize` synchronously reads **current** authentication/grants for `view` and `dispatch`. A receipt lookup checks current view authority again after waits, including when the original conversation no longer exists. A fresh dispatch checks grants and resource preconditions only after the same-key/hash check. Missing, forbidden and unavailable are distinct responses.

Envelope validation preserves all unknown intent fields, rejects non-JSON data and ill-formed Unicode, and freezes the request/context before asynchronous work. The canonicalizer writes sorted UTF-16 object-key pairs directly, preserving array order and ECMAScript number/string serialization. It hashes `{message:<without top-level mid/scope>,target}`. Keys include scope, authenticated principal and mid; outbox references and provider correlations also include principal identity. Different hashes/targets conflict without changing the original record. Concurrent identical requests share the reservation/result; lookup cannot race a reservation to `not_found`.

Handlers have two explicit contracts:

- `apply({state,message,context,entry})` is synchronous and has no external effects. Its typed result and state transition commit together. Declared business errors roll back the attempted transition and commit one rejected receipt.
- `prepare(...)` produces retained input for an external `execute(...)`. Reservation/capacity are committed first, then a dispatch marker, then one adapter call. `execute` must return a typed disposition/result; a thrown, undefined or malformed result becomes unknown. Result replies are allowlisted per family. Credential adapters omit credentials from retained input; R17 supplies those wire adapters.

A handler may synchronously `capture` its live precondition and perform read-only `beforeApply` discovery after historical lookup. Neither may dispatch an effect. A declared discovery/business failure is recorded as a rejected receipt; admission and the adapter revalidate the captured target after discovery. The service captures before its earlier metadata wait as well.

Recovery completes prepared receipts as `ENGINE_RESTARTED` and dispatching receipts as unknown. It retains the original payload and never invokes their handler again. An external effect followed by failed completion persistence remains behind its dispatch marker and returns admitted unknown. Applied/rejected receipts are immutable; resolving unknown requires explicit evidence. The authority refuses new work and authoritative absence on uncertain storage.

After `prepared → rejected`, the phone receives an **admitted** ack with `status:"rejected"`, `outcome:"rejected"`, `result:null`, and `error:{code:"ENGINE_RESTARTED",message:"ENGINE_RESTARTED",retryable:false}`. A repeat or `receipt:get` for the original mid returns `status:"duplicate"`, `outcome:"rejected"` with that same error. No provider call crossed the dispatch marker: after refreshing the target/preconditions, the client may resend its retained intent with a **new mid**. Reusing the old mid only retrieves the recorded rejection. `dispatching → unknown` never authorizes that resend automatically.

Receipt keys use an in-memory Map of authoritative entry positions, rebuilt on load, compaction or reordered state replacement. Appends add only the new bindings; completions reuse the existing index without reserializing retained keys. Transaction/snapshot copies keep their own index version across pruning. A historical duplicate uses the indexed read without cloning or committing the entire state; fresh changes still perform the full JSONL validation/fsync required by the storage contract. The 10,000-entry bound test exercises 100 tail-receipt duplicates, with zero full-state snapshots or commits on that path.

## Send outbox and local state

`engineState` stores current instances, retired instance IDs, folders/assignments, curated settings and account quota/pause state under `values['engine.current.v1']`. It validates restored data before attaching processes or restoring timers. Window session/folder serialization stays unchanged; service mementos are mirrors and never reconstruct the authoritative send queue. No production import or ownership handoff is added.

Send admission allocates a queue ID from a persisted counter plus engine/scope namespace and commits the complete immutable plaintext request, frozen provider launch settings/target, stable principal-qualified correlation, operation and applied/accepted receipt in one JSONL frame. It stores user text/images once, with no 8,000-character or snippet/image truncation. A 16 KiB operation-disposition budget remains reserved while the operation is active, independently of the already final acceptance receipt. Another admission cannot steal that space. Provider acceptance remains active and nonrunnable until completion evidence releases it.

Reclaim measures the full `editPrompt` result before removing work. Reclaim, removal, clear, reorder, folder placement, PR pane metadata and curated setting changes co-commit with their receipt. Duplicates return the original recorded result. Reorder never becomes steer. Local folder writes and provider-derived metadata use the same writer; folder mirrors follow commit. Closing an instance retires its ID, discards its queued work, and preserves uncertain operations and historical receipts. This is an internal state interface, not a new remote administration catalog.

The isolated Claude service projects its queue from the outbox and suppresses checkpoint/window drain timers. Recovery precedes keeper reattachment, quota timers, clients and drain startup. Only explicitly injected fixture providers can auto-start. Before a provider input, the operation is marked dispatching durably and current grants/readiness are checked again. Definite rejection, acceptance, completion and uncertainty are separate operation states; the acceptance receipt never changes. Unknown/dispatching work fences subsequent sends for that conversation. A normal restart drains committed queued work once; backup restore changes scope and quarantines nonterminal work. Same-execution Claude completion may release an operation; evidence-based settlement is available for provider adapters.

## Provider controls and Codex delivery (R15)

`providerControls` is installed only by the service state owner. Ordinary windows retain their existing control APIs and behavior. Claude executions get fresh opaque control generations, each foreground input/observed unsolicited turn gets its own token, and background-only interruption gets a token for the current stoppable set. Real permission events and task starts establish pending identities; transcript rows cannot establish authority. Tasks retain their issuing turn even when background discovery comes during a newer turn. Service init/meta/status expose `run` beside their existing payload, and permission/question/task items carry their issuing markers.

The state adapter captures the actual session, connection, execution, pending object and expected turn synchronously before metadata/receipt waits. It records the precondition and a resource claim with receipt preparation; competing mids cannot acquire it. After any asynchronous owner/connection lookup, the adapter revalidates those exact objects and passes Codex's expected turn through to the write. A known submitted write produces a typed result; a throw, lost response, partial background stop or failed completion persistence stays unknown. Pending keeper connections cannot queue service controls for replay. **Claude has no provider-side turn compare-and-swap**: these checks fence engine scheduling and replacement targets, not an unobservable provider scheduling race.

Engine restart/keeper reattachment rotates control generations. D19's exact eligible keeper run may rebind only real pending/task identities already fsynced in this authority and still matched by the compatible checkpoint plus complete tail. Rebinding changes their advertised run; old controls remain stale, and ambiguous v1 reuse refuses with refresh guidance. An old snapshot without those authority records cannot restore control rights. Consumed/unknown claims survive rebinding. A prepared receipt rejected as `ENGINE_RESTARTED` can release its never-dispatched claim; an unknown dispatch cannot. Keeper protocol remains 1.

Codex send, steer and question inputs use the authoritative outbox with a stable principal-qualified `clientUserMessageId`, frozen input/settings, canonical selected home and opaque account hash. Direct RPC and follower IPC discovery/dispatch phases are persisted before the input write. Raw IPC approval/question requests can establish pending authority only on the selected service connection; their responses retain that exact socket identity. Lost RPC/IPC send, steer or approval confirmation never calls the legacy queue reinsertion or writer-retry paths. An unknown operation or direct-control receipt fences automatic work for the thread; its full input remains retained. Queue promotion keeps its original item until known acceptance and quarantines ambiguity. Read-only owner discovery for a fresh steer precedes acceptance and is revalidated; historical duplicates bypass it.

Reconciliation reads the existing `thread/turns/list` API or exact provider notifications. Matching text/time, an empty page, a timeout or another account/thread cannot resolve uncertainty. Exact user-message `clientId` evidence proves acceptance; a positively correlated turn's terminal state proves completion. A turn ID alone cannot prove an uncertain steer. Explicit authoritative non-acceptance must bind the same account, thread and stable message ID. Both the operation and its linked promotion receipt settle from that proof; restart can finish a lost local receipt commit from already persisted exact proof without provider I/O. Provider versions that omit correlation can leave an operation unknown indefinitely. Reconciliation never changes the original accepted send receipt, automatically retries the input, or takes the writer to replay it.

Transport ownership, thread writer (`engine/external/unknown`) and operation outcome are independent. The borrowed app-server connection and IPC are closed without terminating the external daemon; the owned history reader has separate disposal. The service persists one canonical account selection and rejects a different account in the same authority. The P1 `updateReadiness()` harness gives an immediate refusal for active dispatch or potentially busy owned Codex work; borrowed turns and their retained unknowns do not imply ownership of the daemon. Managed package update/drain remains P2.

## Fleet, hub and remaining mutation families (R17)

`currentState.createSocket({client,server,hub,context,sealed:true,testOnlyV2:true,engine,...})` is the explicit in-process wire composition. A conversation supplies its existing `SessionHub`; a fleet supplies the same `RemoteServer` and its injected services. The primitive socket constructor remains available. This does not enable network v2: `RemoteClient` still forces the P1-24 v1 gate, and ordinary windows keep the legacy path.

The router classifies the current M/Q inventory before dispatch. Unknown mutations never fall through to legacy code. Current device authentication/control is bound to the authority, including queue drain and controls after asynchronous owner lookup; capability, local-only and self/watch exceptions are independent. Creation/resume retains the selected cwd/history/folder and original correlation/result. Settings/snippets use pure authority transitions, with power-setting effects routed through an enabled power adapter. Queue/send/control results keep the previous authority contracts.

Conversation ready records its start/unread effect once. Every successful original/duplicate ready separately sends current init using `hello({snapshotOnly:true})`; it cannot start again or clear a later unread flag. Visible attaches connection state separately from the committed unread transition. Self-forget records an enrollment-bound removal, commits and enqueues its ack, then activates revocation and projects device removal. Startup applies committed removals before admission. An old removal cannot revoke a later enrollment, and revoked principals cannot retrieve privileged results or authoritative missing responses.

PR preparation freezes the linked URL, runner cwd, review thread and failed-check run set before authority waits. Each write uses that plan; partial/lost responses are unknown, never an implicit retry. PR chooser results and late automatic discovery revalidate their original source before changing a link. Original `pr:done` data is retained after relink. Query/draft handlers retain their existing behavior.

Terminal open/run reserve authority-namespaced IDs before spawn; v2 descriptors/live events expose `activeRun`. Stop/close bind the exact observed run or idle null and revalidate the live object/cwd. An uncertain launch/signal/close is unknown and duplicates do not spawn/signal again. V1 descriptors and legacy terminal return contracts are unchanged.

Slack open co-commits the observed seen watermark; duplicate snapshots cannot advance it over newly arriving messages. The Slack runtime restores those watermarks before service polling. Reply records the original posted ts/correlation, and lost post responses remain unknown. Local setup/link open through the captured editor; paired setup/link remain queries. Sign-in/connect/disconnect retain only a safe action plan and allowlisted identity result: no token/cookie, provider error text or credential-bearing envelope is stored or echoed.

Editor/UI plans select their provider at ingress, before receipt or permalink reads. Disconnect, unsupported methods and stale sources do not select another editor. Local document/browser work revalidates after reads; v2 opens URLs in the system default external browser without browser-tab Automation or another-app fallback. Phone navigation never falls back to a laptop editor when its original client disconnects.

`/codex` handoff and Codex local slash commands also enter the full-input outbox. Handoff retains its source context, destination and requester. `/plan`, `/model`, `/effort`, `/goal`, `/review`, `/fork` and `/undo` retain explicit plans; model/undo read-only discovery precedes admission, and later writes revalidate the original execution/resource. Desired Codex choices persist separately from provider metadata. Unknown command/provider writes quarantine their operation while preserving the original accepted send receipt. No legacy command queue, writer takeover, raw-slash prompt or UI automation retry is used. Provider execution is not exactly-once.

Client outboxes remain P1-21/22; network v2 stays gated on P1-24. Real credentials, providers, editor bridges, hardware effects and packaging remain outside this fixture construction.
