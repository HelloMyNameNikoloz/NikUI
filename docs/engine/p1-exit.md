# P1 exit and P2 handoff

R19, 2026-11-20. P1 delivers an extracted engine, a private headless daemon, negotiated current-wire reliability, and isolated development clients. Window mode remains the default. This is an isolated engineering gate; production cutover, a signed production daemon, a menu bar app, actual Mac transcript UI, and real-machine acceptance are P2/P3 work.

## What P1 proves

- The reusable engine owns manager/history/folders/ledger, one canonical Codex account, delivery, Slack, PR/CI, remote resources and injected policy lifetimes. Poisoned child fixtures compose it without resolving VS Code, writing outside their private HOME, connecting to unowned endpoints, or launching real providers/hardware adapters.
- The JSONL authority co-commits complete send input and acceptance, retains receipt scope and provider correlations across reopen, fences corrupt/uncertain storage, and separates immutable acceptance from provider completion. The receipt, disk, limits, mutation, controls, keeper and Codex suites cover the reachable current mutation families, exact run/resource preconditions, competing controls, missing metadata, RPC/IPC ambiguity and current grants. Legacy clients still select v1 independently on each socket.
- Shared JavaScript negotiates only after authentication; it persists exact plaintext before writing, assigns one 128-bit mid per intent, and keeps the host/engine/scope/principal/target binding. Its verified storage refuses failures and the 128-intent/32MiB bounds without clearing the composer. It queries original receipts/operations, retries only an unexpired same-scope authoritative miss with the identical envelope, consumes semantic replies once, and quarantines unknown/downgraded/changed-scope work. Late acknowledgments clear only the matching composition revision. Direct legacy webviews remain v1 unless the development bridge explicitly opts them in.
- The development extension returns before constructing a window manager or keeper. It enrolls through the private control socket, awaits SecretStorage persistence, and registers supported editor methods, workspace URIs and focus on its authenticated connection. Conversation panels use the shared UI. Origin is frozen before disk/provider waits; disconnect/unsupported/lost reply yields a named unavailable/unknown result without retargeting. Disconnecting all clients leaves the daemon alive.
- V2 network advertisement is installed only after the isolated daemon has recovered its authority, composed the engine/resources/bridge, and bound its loopback server. An arbitrary `RemoteServer` with `testOnlyV2:true` still advertises v1. Optional PR/Slack/terminal/voice capabilities follow enabled adapters; editor routing has an actual registered-provider implementation. Disabled actions refuse rather than claim success.
- The composed end-to-end gate uses the actual HTTP/WebSocket server, private JSONL/client files, fake Claude/Codex processes, a private fake Codex IPC router, browser WebCrypto plus shared JS, and the owner-only extension bridge. It proves commit-before-lost-ack recovery, pre-write disconnect/identical-mid resend with fresh crypto counters, deleted-target lookup through fleet, editor origin/disconnect/timeout, RPC and IPC accepted-but-unknown outcomes, and restart without redispatch. Unknown editor work does not incorrectly fence an unrelated provider queue.
- Shutdown closes admission before asynchronous drain. Diagnostics identify phase, current drain stage, completed/failed stages, active dispatch/drain counts and pending editor requests without credentials or prompt bytes. Intentional stop exits 0; crashes/timeouts fail visibly; failed resource drain retains the ownership fence. Managed launchd behavior is still P2.

NikCore P1-22 is the parallel R19 job A, confined to `app/iphone/NikCore/`. The final NikCore test run must be read as a snapshot while that job may still be editing. Its typed client/outbox coverage does not establish a real native phone or Mac UI acceptance run. Node and Swift share `test/fixtures/protocol-v2/`; fixture parsing and runtime evidence remain distinct.

Browser persistence uses verified localStorage under an exclusive Web Lock, including cross-tab receipt updates; an unavailable lock/quota/store refuses a new v2 write while preserving the composer. No memory-only reload recovery is claimed. Bundled JS keys its outbox to the saved host pin, so an address/port change does not silently orphan it. The development webview keeps its own independent pending state through the editor API.

## Reproduce the isolated gate

From this repository:

```sh
node test/run.js engine-client
node test/run.js engine-development
node test/run.js engine-end-to-end
npm test
cd app/iphone/NikCore && swift test
```

The end-to-end runner creates its own private HOME/root, ephemeral loopback listener, synthetic identity, fake providers and private IPC endpoint, and tears them down. It must not be pointed at an existing keeper, Codex daemon or source profile. The CLI-only private-root smoke recipe and permission/refusal rules are in [nikd.md](nikd.md); the [development window recipe](development-window.md) explains the explicit opt-in. No production owner-file switch or source import exists.

In this managed workspace SwiftPM's own sandbox may fail with `sandbox_apply: Operation not permitted`. Job A's reproducible workaround is `env CLANG_MODULE_CACHE_PATH=/tmp/nik-mac/swift-module-cache SWIFTPM_MODULECACHE_OVERRIDE=/tmp/nik-mac/swift-module-cache swift test --disable-sandbox` inside NikCore. These caches are private test/build artifacts; the workspace filesystem restrictions still apply. Record the plain command and any required workaround separately.

## P2 plan — exactly five Codex rounds

1. **Cutover/rollback.** Specify and implement typed local management parity and the selected-scope participant/admission barrier, generation fencing, quiescence, crash matrix and current handback contracts (T48–T55). Include all parity rows above, deliberate folder order/history-delete guards, ownership diagnostics, route/policy ownership design and unsafe-update refusal. Exercise exports/import handoffs with synthetic adapters; production activation stays disabled until the real secret/package gates pass. Require metadata-capable windows and named keeper refusals, never a preference-only switch.
2. **Keychain helper + import.** Build the private stdin/stdout SecItem helper and adapter, selected identity/delivery export and inactive idempotent import, full payload/provenance/hash validation, accounting maxima, import receipts and generation commit/rollback recovery (T41/T48–T54/T66). Prove synthetic locked/denied/corrupt failures without regenerating keys or locking the user's login Keychain. Keep imported work inactive before commit. Recheck helper identity/access on the final bundle in round 3.
3. **Signed bundle + bundled Node + SMAppService.** Package and sign the actual engine/media/dependencies and retained helpers with a pinned official Node; resolve minimum OS and resource relocation. Implement registration/status/start/intentional-stop/crash-relaunch controller behavior, explicit tool/trust/environment handling, packaged notifier/voice, exact route ownership and generation-owned power/notifications (T56–T67). Test final helper signing/access, approval-required/denied/locked states, TCC and update refusal against this package rather than the S6 probe.
4. **Menu bar app.** Ship the enrolled status/start/stop/logs client using typed local management/control schemas. Show generation/account, listener/editor availability, ownership/import/update blockers and unknown outcomes without secrets. Closing the menu client leaves the engine alive; intentional Stop remains distinct. Document project/fleet union and Codex awake/busy aggregation. Do not expand this round into the P3 transcript/composer app.
5. **Real-machine acceptance.** Rehearse the final signed opt-in package with an explicitly selected test profile and real clients/tools. Complete A01–A12 and T63–T72: simultaneous windows, Mac/menu plus phones on one run, lost ack, pending approval restart, legacy-owner refusal, old phone compatibility, exact pins/rekey/delivery, unrelated routes, corrupt/locked storage, minimal environment/TCC, sleep/wake/logout, active Claude/Codex update/refusal and fresh rollback with post-cutover work. Record failures/unrun paths honestly, fix and repeat affected gates, and obtain independent release acceptance. Default-on and P3-G0 remain separate decisions.
