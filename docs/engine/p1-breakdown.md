## Invariants for every PR

Window mode remains the default. Keep its settings scope, restored panels/sessions, local commands, keeper behavior and disposal working. Each row is complete only when `npm test` passes without weakening/removing existing checks, plus its targeted tests; changed Swift code also requires the relevant NikCore suite. Use the existing `test/run.js` exported-function/global-check conventions, with deterministic fixtures. A targeted green run alone is not the full regression gate.

Each PR must state which named test-plan cases it implements and include sanitized results. T01 (the full current runner) is mandatory in every row below. R05 established a 3378/3378 baseline. Run the full suite every round; tests may signal only their own isolated fixture children, never live user processes.

All P1 daemon activity uses a private test HOME, engine/keeper/provider roots, loopback port and synthetic credentials. Inject filesystem/network/power/notification adapters so tests cannot reach production as a fallback. No production import, global route change, local Keychain migration, installed background job or sudoers/pmset changes. The service bridge is development-only against the isolated daemon; ordinary windows continue owning their current engine.

Land changes as inactive/injected features first. Production window traffic remains v1. Isolated nikd advertises at most v1 until the final conformance gate; test-only construction may exercise its developing v2 dispatcher explicitly. Never advertise a v2 core capability while any reachable mutation bypasses the receipt/run/outcome authority. Optional capability means a real enabled handler, not a placeholder.

If a row proves too large, split by module/family while retaining these invariants and the row's final done criterion. Do not bundle unrelated refactoring or opportunistic feature fixes into extraction.

## P1 exit and P2 handoff

P1 exits with a reusable engine, an isolated headless daemon, honest current-wire reliability and development clients. The [R19 exit document](p1-exit.md) records the reproducible private-root gate, exact evidence limits, explicit parity/package blockers and the P2 plan in exactly five Codex rounds. Do not report a signed probe app as the production daemon, or a fixture Mac seat as an actual Mac client.

P2 is split into exactly five Codex rounds, detailed in the [exit plan](p1-exit.md#p2-plan--exactly-five-codex-rounds):

1. Cutover/rollback: typed local management parity, deliberate folder order/history-delete guards, selected-scope participant/admission barrier and generation-fenced current handback; synthetic crash-boundary proofs before production activation.
2. Keychain helper + import: signed SecItem adapter, selected complete export, inactive idempotent import, provenance/hash/accounting validation and failure/rollback recovery. Replace P1 file secrets before production import.
3. Signed bundle + bundled Node + SMAppService: final package/controller/helpers, minimum OS/relocation, TCC/denied/locked access, exact route ownership and generation-owned power/notifications. Verify T56–T67 on the final bundle.
4. Menu bar app: enrolled status/start/stop/logs with named blockers; preserve the distinction between disconnect and managed Stop. Document project/fleet union and Codex awake/busy aggregation.
5. Real-machine acceptance: actual clients and final signed package, A01–A12/T68–T72, active-provider update/refusal and fresh rollback with post-cutover work. Service stays opt-in until the independent default-on gate.

Every affected window must have complete D19 metadata before guarded production resume: any live legacy run without it blocks guarded conversation resumes with `KEEPER_META_INCOMPLETE`. A hello without `metaVersion:1` refuses guarded operations with `KEEPER_META_UNSUPPORTED`; do not replace a live old keeper. A metadata-less checkpoint downgrades eligibility. Prove T48–T54 at every crash boundary before touching real source state.

These are P2 gates, not permission to implement them during the isolated P1 steps. No source-profile-wide mode preference alone can stand in for the generation handoff.
