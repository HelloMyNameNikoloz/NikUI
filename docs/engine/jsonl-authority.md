# P1 JSONL authority

`src/jsonlAuthority.js` implements the P1-12 disk primitive. The isolated daemon opens `<root>/state/authority.jsonl` under its root ownership fence. R13 adds the [receipt dispatcher and current-state/outbox integration](receipt-runtime.md) in explicit in-process v2 construction; network traffic remains v1. Provider-specific controls/reconciliation and complete wire-family routing remain later P1 rows. Test secret adapters and window/service mementos remain separate.

`openAuthority({file, now, fs, limits, hook, readOnly})` accepts a scoped filesystem adapter and integer millisecond clock. Construction returns a writable authority or a diagnostic object; it never replaces an existing invalid authority. `commit(update, {evidence})`, `lookup`, `prune`, `compact`, `restoreBackup` and `close` share one promise lane. Transition callbacks are synchronous and must contain no external effects. They receive a copy; retaining it cannot mutate committed state. A commit resolves only after the complete append and `fsync(file)`. Lookup waits behind already admitted commits and refuses authoritative missing when storage is unavailable. Close drains previously admitted commits.

## Format and validation

Every UTF-8 JSON record ends in LF. A record has exactly `{v:1,type,seq,prev,state,evidence,hash}`. `hash` is lowercase SHA-256 of the JSON serialization of those fields except `hash`, in that order. This detects corruption; it is not authentication against the owner of the private directory. The first record is a `header` with `prev:null`; subsequent `commit`, `resolve` or `restore` records increment `seq` by one and link the preceding hash. Resolution records retain a bounded evidence identifier. Restoration records require a different scope and quarantined work.

Each record contains a complete coupled state image: `{v:1,engineId,scope,clockHighWater,entries,outbox,values}`. This deliberately favors simple atomic validation over incremental encoding in this first implementation. IDs/scopes are independent 128-bit lowercase hex values. Receipt keys include scope, principal and mid. The internal receipt and outbox records retain their original scope across a backup restore; they are never relabeled as fresh requests.

Validation covers JSON types, framing, checksums, versions, sequence/hash continuity, unique keys, request/outbox references, immutable request bindings and final results, retention, result reservations and one-way dispatch/unknown transitions. Unknown can become terminal only with explicit reconciliation evidence; it cannot become queued. The writer computes clock high-water, so transition callbacks cannot rewind it. A rollback greater than 30 seconds blocks new receipt admission while allowing completion/recovery commits. Pruning requires both expiry and `issuedAt + 24h + 30s` to have passed; it retains every unresolved outbox payload.

Malformed complete records, interior corruption, invalid UTF-8, newer schemas, an existing empty file, unsafe paths and unavailable I/O produce diagnostic state and refuse writes and authoritative lookups. A final record without LF is a **torn tail**, even if its JSON parses. Only its validated prefix is exposed through `inspect()` as non-authoritative diagnostic data. The tail is preserved, without automatic truncation or a same-scope reset: an unacknowledged suffix might contain an admitted operation. Explicit recovery must install a new scope and quarantine uncertain work. Ordinary valid reopen preserves the current scope and original results.

## Bounds and durability

Production bounds are 10,000 receipts, 128 MiB of serialized live state plus completion reservations, 1,024 nonterminal outbox intents, 15 MiB per durable payload and 16 MiB per result/error. Pending receipts reserve their bounded result plus 1 KiB of envelope headroom. R13 send operations independently reserve 16 KiB for operation metadata/disposition, plus headroom, until terminal completion/rejection/discard. Provider-accepted and unknown operations remain nonrunnable active entries and retain full inputs beyond receipt expiry. Reservation accounting includes logical and physical completion space; queue IDs, targets, correlations and operation budgets are immutable. Admission never evicts an unexpired receipt or unresolved payload. Over-capacity transitions fail with `RECEIPT_FULL` before append; validation failures leave the writer usable for completions.

The physical log is bounded at 512 MiB. A prospective full frame plus its remaining reservations must fit within half that bound. Before an append would exceed the physical bound, the writer compacts the committed image, then appends the new image. This leaves room for both an old complete image and a reserved completion. A smaller injected physical budget also refuses unsafe admission before append.

Compaction writes a unique `0600` temporary file, fsyncs it, closes it, atomically renames it onto the authority, and fsyncs the containing directory before reopening the append descriptor. The writer rechecks paths, inode/size and its exclusive lock before publication. Orphan temporary files are never promoted: after validating the committed log and acquiring the writer, recovery removes only private regular files in its exact temporary-file namespace and fsyncs the directory. Diagnostic inspection preserves them. Thus repeated crashes cannot accumulate unbounded compaction files; normal compaction needs one additional full-image temporary file. A crash at any compaction boundary leaves the old or new complete authority with its scope, receipts, reservations and unresolved payloads. Short writes are completed in a loop. Append/fsync/rename uncertainty fences the writer; no failure is reported as durable success, and a possibly durable complete record is retained on reopen.

The containing directory must remain owned `0700`; authority, writer lock and temporary files are owned `0600`, regular, single-link entries. Symlinks and foreign ownership refuse; the macOS `/tmp` and `/var` system aliases are the only accepted ancestor aliases. One exclusive pid/token writer lock prevents simultaneous writers. Dead-writer recovery rechecks inode and pid under an exclusive reaper lock; an unproved/live writer or leftover reaper refuses. `readOnly:true` performs diagnostic inspection without creating files, acquiring a writer lock or answering authoritative lookups.

`restoreBackup` is explicitly conservative: it mints a new scope, retains original historical receipt scopes and full inputs, and changes every nonterminal outbox record to unknown. It never makes a copied old queue runnable. Current/quiesced handoff proofs and production import are later work. Storage rollback that bypasses this API cannot be detected from an old valid file alone.

Evidence: `engine-disk.test.js` exercises actual append/reopen, held acknowledgment, partial writes, corruption, read-only/newer/unsafe state, scoped syscall faults, writer drain, physical compaction and self-exiting crash workers at write/file-fsync/rename/directory-fsync boundaries. `engine-limits.test.js` exercises the real 10,000-entry boundary, reservations, expiry/clock high-water and stale-backup quarantine. These establish the storage portions of T16–T21, not provider dispatch ordering or physical power-loss durability.
