# Architecture review, round 2 — Codex

Historical review of draft 1. Findings were dispositioned by D17–D27 and the current architecture/protocol; they are not an additional open-blocker list. R08 status and remaining implementation gates are in [p0-gate.md](p0-gate.md). In particular, P1 uses a private test keeper, S6 supersedes the early signing assumptions, and D27 defers transcript feasibility to P3-G0.

2026-11-20. Reviewed architecture.md draft 1 and spikes.md against the round-1 inventories and source at 132b3c5d5723598699e4ae09176699bfcc4f26f6. References are repository-relative file:line anchors. Findings below are static code evidence, not new launchd, Keychain, signing, or live-process probes. This review does not edit Claude's draft. Proposed resolutions are in decisions.md and protocol-v2.md.

The extraction direction is sound. The draft is not yet a safe implementation contract: it conflates service ownership with existing shared state, treats a receipt as proof of external execution, and adds an unchecked service locator beside an already injected host.

## §1. Goal and non-goals

- Agree with one opt-in engine and retaining Node. “Every UI is a client” is the destination, not what the current wire supports. Rename, sleep/process stop, restart, remove, folder CRUD, device grant/rename, history delete and network administration are extension commands, absent from both dispatchers (src/extension.js:361, :390, :485, :504, :570, :685, :1728; src/remote.js:1011; src/hub.js:381; capabilities.md:86). Turning off extension ownership without bridges for those actions removes working features.
- A “small menu-bar status item” is still a new attended client, with enrollment, notifications, power approvals and lifecycle work. P1 needs a headless harness and diagnostic command first; defer a general Mac client and management RPC catalog.
- Window mode must retain activation order, workspace settings, restoration and disposal, not literally compare every byte of timing-dependent output. Name observable acceptance cases. Current restoration intentionally does not spawn all saved CLIs (src/manager.js:591), while opening a conversation may start one (src/hub.js:708).

## §2. One codebase, two hosts — reject the unchecked global seam

- src/platform/ adapters are a reasonable directory boundary. Calling platform() from engine modules is the wrong dependency mechanism. SessionHub already accepts a host (src/hub.js:72); RemoteServer accepts the composed host (src/extension.js:1005, :1011). Tests create multiple independent hosts directly (test/hub.test.js:27, :39, :155, :216). A late process-wide replacement would make existing objects read a different configuration/store, and tests that instantiate a session before activate() would now fail.
- installHost is not precedent for an unchecked platform singleton. theHost checks installed.manager === manager and otherwise builds an uninstalled host (src/host.js:278, :293). That manager ownership guard is deliberate (src/host.js:27). Keep installHost/forgetHost as the legacy composition convenience; pass services explicitly into manager/host/server factories, captured for their lifetime. Do not require platform installation at module import or for a directly constructed Session/SessionHub.
- Treating host.js/manager.js as the engine dependency work understates extraction. Eleven modules import VS Code; the larger issue is engine composition hidden inside extension/UI modules (inventory-vscode.md:5). slackHome.js is not UI-only: it constructs SlackService, sockets, credentials and change listeners (src/slackHome.js:118, :136, :163, :168, :176). Move that composition to an engine factory while retaining its chrome adapter. extension.js owns voice, terminal, APNs/push, PR/CI, keep-awake and notifications (src/extension.js:832, :939, :984, :991, :1134, :2042). Renaming host imports will not start those services in nikd.
- The proposed store loses globalState/workspaceState separation. Manager reads both and prefers nonempty workspace state over Durable (src/manager.js:140, :557, :581); folders do likewise (src/folders.js:32, :54). Preserve explicit workspace/place provenance; a flat per-key store cannot represent two windows' sessions under the same key.
- Config needs context and provenance, not just get/inspect/set. Snippets merge shipped defaults and write to the scope already holding a value (src/manager.js:86; src/host.js:138; src/settingsMenu.js:135, :203). A daemon config.json cannot silently become the effective replacement for every workspace. Proposal: inject a legacy adapter unchanged; service mode uses engine settings plus explicitly imported project settings, with machine executable/network/secret policy restricted to the local owner.
- SecretStorage uses store/delete/get plus a change event, and consumers rely on changes to rebuild (src/slackHome.js:163, :217, :255). Specify its adapter and disposables; don't assume a set-only replacement is equivalent. UI requests need deadlines/cancellation and typed outcomes; one generic boolean default is insufficient for a credential flow, informational notification and lid setup.
- For one user, a clock/logger/config/store framework, one JSON file per arbitrary key, a schema interpreter and generic file watcher are unnecessary P1 work. Use narrow object adapters, injected timers only where tested, and version authoritative envelopes first. Cache migrations and a universal UI broker can wait.

## §3. Process layout — keeper coexistence and Codex ownership are underspecified

- Keeper is one per user, not one per engine (src/keeperLink.js:35). It has exactly one owner per run and forwards output only to that owner (src/keeper.js:67, :204). Both attach and reclaim refuse another live owner (src/keeper.js:330, :348). nikd cannot be “another client” and simultaneously control a legacy-owned run. Preserve the owned/elsewhere response, never steal or spawn a replacement.
- Keeper's key is the NikUI instance ID, not Claude's conversation ID (src/keeperLink.js:365, :376, :402). Its spawn case rejects duplicate runId only (src/keeper.js:295). Two imported/resumed instances with different IDs can still launch two CLIs against one transcript. The draft needs an explicit ownership fence before importing/resuming, not an assumption that keeper arbitrates all conversation writers.
- KeeperLink also falls back to a direct child when connection fails (src/keeperLink.js:369), and attach can return false after repeated connection failures (src/keeperLink.js:401). Those are legacy availability choices, not proof that another run is absent. Service mode must fail closed for uncertain imported ownership instead of using either path to launch a replacement. Keep the legacy fallback behavior separate.
- Orphan grace is three minutes and checkpoints/tails/approval dedupe live only in RAM (src/keeper.js:43, :55, :75, :215). “A nikd restart/update does not end runs” is conditional on timely compatible reattachment; a deliberate long Stop Engine does not preserve them indefinitely. A keeper crash/reboot loses that continuity.
- The keeper lock does not use start time or flock. It stores only a PID and tests lock age, with a breaker/hardlink scheme (src/keeper.js:393, :403, :412, :426). Do not copy it while describing stronger semantics. Prefer launchd owning the managed instance, plus a private exclusive bind/control handshake; reject a second manual instance. A stale/unresponsive endpoint is not permission to unlink a live one.
- Process ownership and thread writer ownership are separate axes. Borrowing the ChatGPT daemon is already restricted to the app account (src/codex.js:88; src/codexHome.js:33); accountHome('work') can fall back to personal (src/codexHome.js:25). Record the resolved home, do not infer it from a label.
- “Borrowed never stopped” already means close our connection: the borrowed proc.kill closes WS, not the external daemon (src/codexSocket.js:196, :216). Preserve that behavior, including failed initialization cleanup (src/codex.js:151, :227). Also track the owned history-reader child created while borrowing (src/codex.js:1558).
- IPC failure is not automatically thread read-only or definitely rejected. Direct turn/start can also lose its reply (src/codex.js:1087, :1093); the follower path actually requeues after any error (src/codex.js:1209, :1214). Persist an operation as unknown, freeze its dispatch lane, and reconcile by a stable provider correlation. An owned app-server can serve a thread whose writer belongs to the app; a borrowed server is not inherently read-only.
- Coexistence proposal: P1 nikd uses separate state/receipt files, loopback port and new test instances; tailnet and import off. It may share the existing keeper only for disjoint instances and must respect live owners. Production cutover fences all source windows before importing IDs. An old/uncooperative extension cannot be made safe by a new setting it doesn't understand.

## §4. Clients and trust

- Application capability claims and authority must be separate. Today's authority comes from the authenticated seat (src/auth.js:58, :209); hub local checks use device.kind (src/hub.js:189, :208). A hello field or self-supplied from.local must never grant local privileges. A registered extension over WS otherwise looks like a paired remote device and currently loses local UI behavior.
- The table lists browser WS as loopback, but the same served browser can arrive through tailnet/tunnel and authenticate as a paired device (src/remote.js:926, :967; src/auth.js:179). Preserve LocalKey versus paired-seat distinctions, Host/Origin checks, app-only and encryption opt-outs in legacy mode.
- Enrollment-only-over-control-socket concerns NEW local app/editor grants. Existing phone pairing remains HTTP POST /pair (src/remote.js:795); don't accidentally remove it. A page must never receive the native extension's enrolled key.
- Peer-UID native check/lsof fallback contradicts spike S3. lsof is a diagnostic, not proof of the connecting peer. For this Mac, a verified owned 0700 directory and private socket are a coherent same-UID trust boundary (src/keeperLink.js:42); native peer verification can be added with the app. Document what is actually enforced.
- Fail-closed imported identity is correct; also protect VAPID. Both loaders currently replace undecodable keys (src/identity.js:21; src/push.js:35). Choose a source profile explicitly: “existing identity” is not necessarily one universal VS Code profile. Grants/delivery material must migrate with that key; never union grants from unrelated identities.

## §5. Editor capability provider

- Server-derived requester context is needed at every call site; only setSetting currently passes even a local boolean (src/hub.js:592). openFile and runInTerminal drop requester identity (src/hub.js:644, :654), while switch treats any device as navigation, not an editor provider (src/hub.js:660). A routing paragraph alone does not fix these branches.
- First route an editor-origin action to that exact live provider; then choose a provider covering the resource/workspace (longest matching URI root), then a focused eligible provider. A phone choosing a conversation must continue navigating only that phone. An explicit provider that disappears should return unavailable, not reroute a command to another window.
- Register provider ID, connection lifetime, supported methods, workspace URIs and focus state from a locally enrolled extension. Unregister on disconnect. No separate distributed lease/timer service is needed for one Mac; focus is advisory and does not establish attendance or grant authority.
- Preserve file kinds, relative cwd and line selection (src/host.js:228). Carry URI scheme/authority for workspace identity; do not flatten all projects to fsPath (src/durable.js:15). Existing remote creation is limited to offered projects (src/remote.js:1154); taking a union of all windows broadens visibility/start authority and is a new service-mode policy, not “today's rule.”
- Terminal.app “typed, not run” is not an implemented substitute for VS Code sendText(command, false) (src/host.js:217). P1 should return EDITOR_UNAVAILABLE when no insertion provider exists. Do not add AppleScript terminal automation merely to make every capability appear available.
- Fallback URL opening must use the system default external browser. open -a "Visual Studio Code" is also an unjustified assumption about the user's editor variant. Finder/system opens can be explicit fallbacks where equivalent; browser-tab focus/TCC is optional (src/host.js:48), not a prerequisite for URL opening.
- Origin is also lost for delayed Codex fork/open events: lastSender is one mutable field (src/hub.js:104, :504). Carry per-operation origin through asynchronous handoff/fork; otherwise another send can move the wrong client's panel. engine.machine cannot own handOff's UI navigation.
- Quota confirmation currently resumes every manager instance and has window semantics (src/host.js:64). In service mode define account-wide scope and a single correlated, expiring local response; a phone-triggered send must not raise a laptop modal. Separate lid authorization/setup from flipping a previously approved setting (src/extension.js:843).

## §6. Protocol — draft guarantees are too strong

- There is no application hello/welcome today. Authentication is @challenge → @auth → @welcome, usually inside @box (src/remote.js:1828, :1843, :1905); hello is only a hub method or keeper message. Add negotiated application hello/welcome after authenticating, with an additive advertisement in @welcome so new phones detect an old extension without racing a timeout.
- Same mid prevents redispatch only while a trustworthy receipt exists. Define principal/scope, canonical request hash, concurrent duplicates, expiry, storage exhaustion, crash ordering, and mismatched-payload rejection. Evicting at 10k before 24h and treating the next miss as fresh would replay work.
- Persist-before-effect still has a crash gap around external I/O. Pending/unknown outcomes are needed in addition to applied/duplicate/rejected. A duplicate of a rejected result must remain rejected, not appear successful.
- submit() returning “sent” is not acceptance (src/session.js:619; src/codex.js:895); the hub doesn't await provider work (src/hub.js:511). A durable engine-outbox acknowledgment must be distinguished from provider acceptance. Memento update isn't awaited and queued images are dropped today (src/manager.js:36, :557).
- Approval IDs aren't globally unique. Claude only checks isRunning before forwarding (src/session.js:779); Codex removes its pending RPC before writing (src/codex.js:1350). Bind the pending record and answer to an execution/turn generation; serialize competing answers even when they have different mids. Capture a stop turn before async owner lookup (src/codex.js:1113).
- Queue IDs can also collide after restoration: _seq resets while existing q.id values are kept (src/session.js:209, :214, :625). A fresh delayed unqueue/edit/promote must not target another prompt assigned that old ID. Persist nonreused entity IDs; mid deduplication doesn't replace resource identity.
- Steer is hidden in send('/steer ...') and promoteQueued (src/codex.js:1030, :1133), not a new wire type. Background stopTask may belong to an older turn. Terminal stop currently targets whichever run is current when processed (src/remote.js:1690). Cover these identities explicitly.
- ready starts a process, visible clears unread, pr:pane persists shared state, @listen rotates a secret, and slack:open suppresses escalation (src/hub.js:199, :394, :708; src/remote.js:239; src/slackRoom.js:172). A mutation list copied only from STEERING misses these.
- protocol-v2.md supplies exact envelopes, limits, failure behavior, full current message classification and compatibility. It deliberately does not promise event replay or externally exactly-once execution.

## §7. State and storage — single writer is a migration boundary

- Durable already reads/modifies/replaces one G/remembered.json for all places; the temp path is fixed, there is no cross-process lock, and errors are swallowed (src/durable.js:61, :89). Atomic rename protects whole-file visibility, not concurrent updates or shared .tmp collisions. “One writer per file” is not today's window-mode invariant.
- Ledger does a read/merge but also uses a shared .tmp without a lock (src/ledger.js:49, :125). A max merge doesn't serialize two windows racing a write. Service state must have a new private root; nikd must not adopt these live files as its backing store.
- Extension engines cannot merely stop writing “global engine keys”: sessions/folders are workspace keys, Durable stores several places, and the backup is not complete (src/manager.js:550, :581; src/durable.js:15; inventory-state.md:7). Preserve workspace folders, byConversation assignments, names, quota override/pause, complete queues, instance IDs and ledger maxima with a source receipt.
- One writer applies to NikUI-owned authoritative state. Claude transcripts, Codex homes, Keychain and OS notifications retain their real owners (inventory-state.md:36). Do not copy provider DBs/credentials or claim nikd is the sole writer to them.
- Agree with private files and fail-closed newer authoritative schemas. Specify awaited commits and receipt/outbox ordering. A generic update promise backed by the existing fire-and-forget memento callers does not establish durability.
- Do not make fsync/schema migrations for every cache a P1 gate. Version engine metadata, receipts, queues and migration receipts; discard/rebuild incompatible derived caches. Namespace Codex cache/session keys by resolved home before supporting several accounts (src/codex.js:41; src/codexCache.js:65).

## §8. Lifecycle

- “Drain” is three policies: update/restart, deliberate stop and logout. No generic owned-work checkpoint exists for Codex, terminal commands, voice builds or in-flight Slack/gh requests (src/codex.js:1696; src/terminal.js:144; src/voice.js:193; src/slack/api.js:63). Bound drain time; wait for owned Codex turns or explicitly report they cannot be preserved. Never imply keeper holds them.
- On manual Stop Engine, released Claude runs expire at keeper grace; on update, require reattachment inside that grace. Logout/reboot is not a guaranteed safe handoff because keeper state is RAM and it is not a boot service (src/keeper.js:55, :215).
- “Crash + receipts makes it idempotent” must become “recover receipts, quarantine dispatching operations, reattach compatible runs, reconcile uncertainty.” Neither provider reply loss nor keeper loss is cured by a journal.
- KeepAlive policy must distinguish intentional stop from restart. Exiting 0 is not by itself sufficient with unconditional KeepAlive; reconcile SMAppService status with the actual configured launch policy before claiming Stop Engine works. Spike S1 proves a RunAtLoad probe environment, not this lifecycle.
- Power and local notification ownership need an explicit service owner. Busy inputs currently use Claude manager only (src/extension.js:839), caffeinate watches the host PID (src/awake.js:80), lid watchdog removes holders after host exit (src/lid.js:108), and delivered notification clicks target a per-window inbox/editor (notifier/main.swift:92). Retargeting these to a daemon changes real behavior; don't duplicate local banners or silently keep a lid policy alive forever after closing all windows.
- Full sleep/wake polling and a generic background-task supervisor can be deferred; revalidate on reconnect/read first. Preserve existing power defaults and use the existing helpers deliberately.

## §9. Modes and cutover

- Agree: unreachable service must not silently start a second engine. But “Use window mode” also needs a confirmed handback of writer ownership; an unreachable daemon is not proof it stopped. Do not automatically remove its socket/lock or use a stale backup while it might still run.
- The idle check “or runs handed to keeper” is insufficient: another legacy window may own the run, several windows may still flush the same Durable file, and a third can reconnect during import (src/manager.js:496; src/extension.js:193; src/keeper.js:348).
- Proposal: explicit source-profile/workspace manifest → quiesce all participating upgraded engines and flush → snapshot/export through their APIs → import to isolated root with stable import ID/hash → verify identity and counts → commit owner generation → connect clients. Unacknowledged/old source windows block production import; P1 isolated service remains usable.
- A second import must not overwrite newer service settings/queues or union grants. Rollback after service writes requires a new export/handback or explicit restoration with known data loss, not simply “reverse switch.” Receipts/operation state travel with handback or the receipt scope changes and clients stop replaying.
- Changing receipt scope alone does not make a backup safe to run: an entry queued at backup time may have executed later. Restored nonterminal outbox entries must be quarantined unless a current quiesced handoff proves they remain undispatched.
- Global fleet/projects/folder union, settings scope and notification audiences are service-mode choices needing acceptance. Preserve the legacy window partition instead of quietly globalizing it.

## §10. Packaging and spikes

- architecture §10 requires Developer ID/notarization while spike S2 says the available Apple Development identity is enough for this Mac. Resolve in favor of the one-Mac goal; distribution signing is not a P1 dependency. S2 does not include a registration/login/restart transcript, unlike S1's actual environment probe; record it as a packaging assertion to verify, not a passed acceptance test.
- Accept S1's minimal PATH finding. Cache the binary lookup separately from a sanitized child environment; subprocess tools need PATH too (src/session.js:394; src/codex.js:117). Do not run interactive login-shell startup on every request. trust-dir wrapper behavior and fresh-project CLI startup remain unverified, explicitly as S1 says.
- Pin/check the actual Node artifact and packaged dependencies in P2. “Official Node is statically linked” and the required hardened-runtime entitlements are not established by inspecting Homebrew Node. Avoid granting optional executable-memory entitlements without a failing packaged test.
- Accept S4: extension-pushed export, never directly read live state.vscdb. Include workspaceState and files/provenance, not just the globalState list.
- S5 shows security CLI CRUD works for probe data; it doesn't prove arbitrary stdin secret quoting, launchd/locked-keychain behavior or identity failure handling. Test those without logging secret values. Prefer one small SecItem helper when bundling it is simpler than a bespoke interactive security command encoder; do not put secrets in argv.
- Avoid a custom updater, broad native helper framework, universal filesystem checks and distribution pipeline in P1. A pinned local Node launch, private state, explicit status and reproducible bundle later are enough.

## §11. Testing and acceptance

- Same-process tests currently share a cached VS Code stub (test/helpers/vscode-stub.js:145); this does not justify another mutable singleton. Add a contract where two managers/hosts with different stores/configs exist concurrently and remain isolated, plus no-vscode import tests for the headless graph.
- Run legacy behavioral tests unchanged by default, then opt-in v2 tests. A memory store cannot prove disk receipt recovery; use a temp private receipt file and deterministic crash points around reserve/dispatch/commit. Verify duplicate rejection, scope reset, capacity/expiry, current grants and target deletion.
- Most important mixed-mode test: two source windows plus nikd, including an already-owned keeper run and another imported ID for the same conversation. Verify no takeover/duplicate spawn, no remembered/ledger writes from nikd into source storage, and no tailnet-route theft.
- Provider fakes must model accepted request + lost reply, direct AND follower IPC, concurrent approval answers, stale stop after a new turn, queue images across restart and borrowed connection cleanup. A passed request/response happy path is insufficient (src/codex.js:1214).
- Add routing tests for two workspaces, originating provider disconnection, no editor, phone switch, delayed fork origin, no attended local confirmation, and external browser fallback. Test legacy scope-aware settings separately from daemon import.
- Acceptance needs notification/power ownership, identity/VAPID corrupt or locked stores, signed minimal-environment launch and manual-stop versus crash behavior. Mark unprobed cases honestly. This docs-only round runs static reference/coverage checks; it does not run process-controlling tests or repeat Claude's live probes.
